## 一、隱私承諾是否被兌現

### P1　影片、畫面、骨架座標有沒有離開瀏覽器 —— ✔️ 通過

- **程式檢查**：影片只用瀏覽器內部的暫時網址（`blob:`）播放與逐格讀取；畫面交給「背景執行緒」（Web Worker）裡的 MediaPipe 找骨架，
  用完立即釋放。全站只有一個地方會對外送資料：`src/lib/report/fetch-report.ts` 呼叫本網站的 `/api/report`。
  骨架座標（每格 33 個關節位置）只用在瀏覽器裡計算角度與畫回放，**沒有任何程式把它送出**。
- **實測**（Playwright 在正式版網站上操作，記錄瀏覽器發出的每一個連線，包含背景執行緒）：
  走完首頁 → 拍攝教學 → 上傳 → 分析（實際載入 MediaPipe 模型、逐格偵測）→ 請重拍頁 → 示範報告，
  **所有連線都只到本網站**；唯一的「送出資料」是示範報告的 `POST /api/report`（約 1.2 KB 的角度與判斷結果）。

### P2　MediaPipe 內建的「使用統計」回傳 —— 低 ／ ✔️ + ✅

MediaPipe 程式裡寫死了每分鐘把使用統計（任務類型、作業系統、處理速度，不含影像）送到 Google（`odml.pa.googleapis.com`）。
前端工程師原本已在背景執行緒中把對外連線擋下（`src/lib/pose/pose.worker.ts`）。
本次再加上瀏覽器層級的「內容安全政策」`connect-src 'self'`（見 A1）：**就算程式層的攔截被繞過，瀏覽器本身也會拒絕連到其他網址**。
已確認背景執行緒的程式檔也帶有同樣的政策。MediaPipe 只在背景執行緒中載入，主畫面不會執行它。

### P3　第三方腳本、字型、分析工具、錯誤回報 —— ✔️ 通過

沒有任何第三方腳本、追蹤碼、網站分析（例如 Google Analytics、Vercel Analytics）、錯誤回報服務（例如 Sentry）；
字型使用裝置內建字型，不從網路下載；模型與 WASM 都放在本網站（`public/mediapipe/`）。
主控台的錯誤訊息只留在使用者自己的瀏覽器，不會被送出。

### P4　送到 `/api/report` 的內容 —— ✔️ 通過

- 前端用 `toReportRequest()` 逐欄挑選要送的資料：可信度等級、走了幾趟、各問題的等級與**一個**代表角度、問題出現的秒數、
  是否勾選「適用族群提醒」（只有是／否，不含勾了哪一項，符合 D35）。
- 內部完整結果 `details`（含左右側）在型別上就不在送出的資料裡，伺服器端也用嚴格格式檢查（多一個欄位就拒絕），
  所以就算前端寫錯，伺服器也不會收下。
- **本次新增自動測試**（`src/lib/report/fetch-report.test.ts`）：確認送出的 JSON 只有 7 個允許的欄位，不含 `details`、左右側、影像等字樣。

### P5　伺服器紀錄 —— 資訊 ／ ✔️ + ⏸

- 我們的程式只在出錯時記錄「錯誤類型」（例如「逾時」），不記錄請求內容、角度或 AI 文字（D18）；Claude 套件的日誌也已關閉。✔️
- 但部署平台（Vercel）本身會記錄每個請求的**時間、網址路徑、IP、瀏覽器類型、狀態碼**（不含請求內容），這是平台功能，程式無法關閉。
  ⏸ 建議隱私頁揭露「網站主機會保留一般連線紀錄」（保存天數以 Vercel 方案為準）。【需法律審閱】

### P6　瀏覽器儲存 —— ✔️ 通過

實測分析完成後檢查瀏覽器：沒有 Cookie、沒有 IndexedDB、沒有快取儲存區、沒有 Service Worker。只有兩個小設定可能出現：

| 位置 | 名稱 | 內容 | 何時寫入 |
|---|---|---|---|
| sessionStorage | `postures:in-app-banner-dismissed` | `"1"` | 在 LINE 等 App 內建瀏覽器按「我知道了」；關閉分頁就消失 |
| localStorage | `postures:pose-delegate` | `"CPU"` 或 `"GPU"` | 網站**不會**寫入，只有開發者手動設定用來量測速度 |

影片、骨架、分析結果、報告都只存在分頁的記憶體裡，重新整理就消失。

### P7　隱私頁的「處理完不會保存」—— 中 ／ ⏸ 需法律審閱

`/privacy` 寫著「這些數字由人工智慧服務處理，處理完不會保存」。**我們的伺服器確實不保存**，
但資料會送到 Anthropic（美國）處理，Anthropic 依其商業條款**可能會保留 API 的輸入與輸出一段期間**（例如做濫用偵測），
期間與條件以 Anthropic 官方公告為準；若要「零保留」，需要另外向 Anthropic 申請。
建議改成「我們的伺服器不會保存；AI 服務商依其政策處理」之類的精確說法，並揭露資料會送到國外處理（UX 文件 §2.0 已提醒）。
這是文案與法律問題，不在本次程式修改範圍（檔案在 `src/app/privacy/`）。

### P8　流量限制暫記 IP —— 資訊 ／ ⏸

新加的流量限制（C1）需要用 IP 計數：IP 只放在伺服器記憶體中，**最多一分鐘就清掉**，不寫入紀錄或任何儲存。
建議隱私頁一併說明「為防止濫用，會短暫使用連線位址計數」。【需法律審閱】

## 二、API 安全

### A1　全站安全標頭 —— 中 ／ ✅ 已修正

原本網站沒有任何安全標頭。本次在 `next.config.ts` 對所有網址（包含頁面、API、靜態檔、背景執行緒程式）加上：

| 標頭 | 作用（白話） |
|---|---|
| `Content-Security-Policy`（內容安全政策） | 規定網頁可以從哪裡載入東西、可以連到哪裡。重點如下 |
| 　`default-src 'self'`、`connect-src 'self'` | 只能連回本網站，**資料無法被送到其他網址**（P1、P2 的瀏覽器層級保證） |
| 　`script-src 'self' 'unsafe-inline' 'wasm-unsafe-eval'` | 只執行本網站的程式；允許 MediaPipe 的 WebAssembly |
| 　`worker-src 'self'` | 背景執行緒只能載入本網站的程式 |
| 　`media-src 'self' blob:`、`img-src 'self' blob: data:` | 允許播放使用者自己選的影片與本機產生的關鍵畫面 |
| 　`frame-ancestors 'none'`、`object-src 'none'`、`base-uri 'self'`、`form-action 'self'` | 不能被其他網站嵌入（防點擊劫持）、不能載入外掛、防止網址竄改 |
| `X-Content-Type-Options: nosniff` | 瀏覽器不會「猜」檔案類型（防止把上傳的檔案當程式執行） |
| `Referrer-Policy: no-referrer` | 點到外部網站時不透露使用者從哪一頁來 |
| `Permissions-Policy` | 關閉相機、麥克風、定位、付款、USB 等用不到的功能；保留螢幕不關閉（分析時）、全螢幕、複製網址 |
| `X-Frame-Options: DENY` | 舊瀏覽器的防嵌入備援 |
| `Cross-Origin-Opener-Policy`、`Cross-Origin-Resource-Policy` | 與其他網站的視窗、資源隔離 |
| `Strict-Transport-Security` | 只能用 HTTPS 連線（Vercel 預設也有；本機 http 會被瀏覽器忽略） |

**實測**（正式版 `next start`＋Chromium）：首頁、拍攝教學、上傳、隱私、免責、請重拍、示範報告（含列印版）都正常；
上傳後實際載入 MediaPipe 模型並逐格偵測（測試圖樣影片 → 請重拍「找不到人」；真人背面影片 → 請重拍「不是側面」，代表有偵測到人）；
分析頁的影片（`blob:`）正常播放；**沒有任何安全政策違規訊息**；開發模式（`npm run dev`）也正常。
既有的 17 個端對端測試全部通過。

> 備註：主控台會看到幾行 MediaPipe 自己印的訊息（例如「Created TensorFlow Lite XNNPACK delegate for CPU」被標成錯誤），
> 這是 MediaPipe 內部的狀態輸出，與安全政策無關，加政策前就存在。
>
> 未能實測的部分：手邊的公開真人影片都沒有通過「側面、完整入鏡」的條件，所以沒有走到「報告頁＋骨架回放」。
> 回放用的是同一個 `blob:` 影片網址與畫布，已在分析頁實測可播放；請測試成員用真人側拍影片（`E2E_WALK_VIDEO`）跑一次完整流程確認。

### A2　輸入驗證與請求大小 —— ✔️ 通過

- 只接受 `Content-Type: application/json`；請求大小上限 16 KB（先看宣告大小，再邊讀邊數，超過立即停止）。
- 用 zod 嚴格檢查：多一個欄位就拒絕；所有文字欄位都是固定選項；數字有上下限；陣列有長度上限；問題與指標、原因代碼必須對得上。
- 其他 HTTP 方法（例如 GET）自動回 405。

### A3　錯誤訊息 —— ✔️ 通過

格式錯誤時只回「欄位路徑＋錯誤類型」（例如 `rules_version / invalid_format`），**不回傳使用者送來的值**；
伺服器錯誤只回 `internal_error`，不含程式細節。本次補上自動測試（送入 `<script>` 字樣，確認回應中不會出現）。

### A4　API 金鑰會不會進入網頁 —— ✔️ 通過

- 呼叫 Claude 的程式標註 `server-only`，一旦被網頁端引用，建置就會失敗。
- 金鑰只從伺服器環境變數 `ANTHROPIC_API_KEY` 讀取，沒有任何 `NEXT_PUBLIC_` 開頭的變數。
- 搜尋建置後送到瀏覽器的所有檔案（`.next/static`）：沒有金鑰名稱、`sk-ant-`、Anthropic 網址、也沒有給 Claude 的提示詞內容。
- `.env*.local`、`.env` 已列入 `.gitignore`，`.env.example` 只有空白欄位。

### A5　提示詞注入 —— 低 ／ ✔️ 通過

「提示詞注入」是指使用者在資料裡夾帶指令，騙 AI 做別的事。本產品的風險很低：

- 使用者能送的內容全部是固定選項、數字或是／否；唯一的自由字串 `rules_version` 只允許英數與 `._-`、40 字以內，而且**不會送進給 Claude 的資料**。
- 給 Claude 的資料（`buildAiInput`）全部由伺服器用審閱過的文案與動作庫組成。
- Claude 的回覆必須是指定格式，卡片與練習代碼必須是程式提供的；每段文字都經過禁用詞、左右側、頭部、數字、長度檢查，不合格就換回範本；
  畫面以純文字顯示（全站沒有 `dangerouslySetInnerHTML`），不會被當成網頁程式執行。
- 本次補上自動測試：在 `rules_version` 放入「忽略先前指示」字樣，確認它沒有出現在送給 Claude 的任何參數中。

### A6　從其他網站的網頁呼叫本 API —— 低 ／ ✅ 已加檢查

瀏覽器本來就會擋下其他網站對本 API 的 JSON 請求（需要對方網站取得許可，而本 API 不給許可）。
本次再加一道：瀏覽器標示為「跨網站」（`Sec-Fetch-Site: cross-site`，網頁程式無法偽造）的請求直接回 403。

### A7　連線中斷造成未處理錯誤 —— 低 ／ ✅ 已修正

讀取請求內容時若連線中斷，原本會丟出未處理的錯誤；現在回 400，不影響其他請求。

### A8　`X-Powered-By` 標頭 —— 資訊 ／ ✅ 已移除

`poweredByHeader: false`，回應不再透露網站使用的框架。

### A9　安全政策允許行內程式 —— 低 ／ ⏸ 保留

網站頁面是事先產生好的靜態頁，Next.js 會在頁面中放入「行內程式」來啟動畫面，所以 `script-src` 需要 `'unsafe-inline'`。
更嚴格的做法（每次請求產生一次性密碼 nonce）會讓所有頁面改成每次即時產生（變慢、伺服器費用增加），並要修改全站外框檔。
目前網站**沒有任何使用者輸入會被當成網頁內容顯示**，也沒有第三方腳本，被插入惡意程式的機會很低；而「資料只能送回本網站」的保證（`connect-src`）不受影響。
建議在開放資料捐贈（M6，會連到 Supabase）或加入任何第三方服務前重新評估。

### A10　骨架偵測背景程式的原始碼被公開 —— 資訊 ／ 📝 轉知前端

建置工具（Turbopack）除了打包背景執行緒程式外，還把原始檔 `pose.worker.ts`（含中文註解）原樣複製到
`/_next/static/media/pose.worker.<亂碼>.ts`，任何人都能下載。內容沒有機密（就是 repo 裡的程式），所以只是資訊。
原因是 `src/lib/pose/pose-detector.ts` 的 `new Worker(new URL("./pose.worker.ts", import.meta.url))` 在伺服器端打包時被當成一般檔案。
不在本次修改範圍，請前端工程師評估是否處理（例如只在瀏覽器端建立背景執行緒的程式路徑中引用）。

不需要升級任何套件。

### D2　骨架偵測模型與 WASM 的來源 —— ✔️ 通過

模型在建置時從 Google 官方模型庫下載，並**核對 SHA-256 指紋**（被竄改就停止建置）；WASM 來自版本固定的 npm 套件（由 `package-lock.json` 鎖定）。
使用者瀏覽器只向本網站下載這些檔案。

## 四、費用濫用

### C1　公開 API 可被大量呼叫 —— 高 ／ ✅ 已修正（免費、記憶體內）

`/api/report` 不需要登入，任何人都能用程式連續呼叫；設定金鑰後，每次呼叫約花新台幣 1–3 元的 Claude 費用。
本次在 `src/lib/report/rate-limit.ts` 加上三道限制，**不需要任何外部服務或帳號**：

| 限制 | 數字（每台伺服器） | 超過時 |
|---|---|---|
| 同一個連線來源（IP） | 每分鐘 10 次 | 回 429「請稍後再試」，附等待秒數；使用者的瀏覽器會自動改用固定範本組報告，照樣看得到報告 |
| 整台伺服器 | 每分鐘 120 次 | 同上 |
| 請 Claude 撰寫 | 每分鐘 20 次、每小時 300 次 | **不回錯誤**，直接回固定範本報告（不產生 Claude 費用） |

設計細節：

- 已超量的 IP 不會佔用整台的額度，避免單一來源拖累所有人。
- IPv6 以 /64 為單位計數（同一個家庭或裝置通常共用），避免換位址繞過。
- 記憶體用量有上限，不會因大量不同 IP 而耗盡。
- 一般使用者一次分析只呼叫 1 次；同一網路（公司、學校、行動網路）可能共用 IP，所以每分鐘 10 次留有餘裕。
- 想調整數字：改 `rate-limit.ts` 最上方的 `REPORT_RATE_LIMITS`。

> 最壞情況估算：每台每小時最多 300 次 Claude 呼叫 ≈ 每台每小時新台幣 300–900 元。
> 這個上限是「每台」計算（見 C3），所以**最後防線仍是 Anthropic 後台的每月花費上限**（SPEC H2，必做）。

### C2　示範報告每次打開都呼叫 Claude —— 中 ／ ✅ 已修正

`/report/sample` 每次被打開都會用同一份假資料呼叫 API；設定金鑰後，等於每位訪客看示範頁都花一次錢。
現在伺服器會把示範報告的 AI 版本暫存 1 小時（`src/lib/report/sample-cache.ts`），多人同時打開也只呼叫一次。
只有「內容與示範假資料完全相同」的請求才會用到暫存；**真實使用者的分析結果一律不暫存**（D18）。

### C3　記憶體內流量限制的先天限制 —— 中 ／ ⏸ 保留

- **Vercel 會依流量同時開多台伺服器**（也可能分散在不同地區），每台各自計數，所以實際上限是「每台上限 × 台數」；
  伺服器閒置或重新部署後會重開，計數歸零。這道限制是「減速丘」，不是保證。
- IP 取自 `x-forwarded-for`／`x-real-ip` 標頭：**在 Vercel 上由平台覆寫、使用者無法偽造**；
  如果將來改成自行架設、而前面沒有可信任的反向代理，使用者可以偽造 IP，此時只剩「整台上限」有效。
- 有心人可以用大量不同 IP（例如殭屍網路）同時呼叫；此時「整台上限」與「Claude 次數上限」會先擋住費用，但正常使用者也會暫時拿到範本版報告。

正式營運時的建議方案列在第七節。
